# 串口通信与 VOFA+ 使用指南

本文依据 2026-10-03 的 [usart.c](../Core/Src/usart.c)、[foc_vofa.c](../User/foc_vofa.c)、[foc_vofa.h](../User/foc_vofa.h)、[main.c](../Core/Src/main.c) 和 [foc_manager.c](../User/foc_manager.c) 编写。参数和命令对应当前固件；上位机界面入口可能随版本变化，本文以操作目的和协议设置为准。

配套阅读：[工程总体说明](01_工程总体说明.md)、[FOC模块与算法详解](02_FOC模块与算法详解.md)。

## 1. 串口通信的基本概念

### 1.1 UART、USART与异步通信

UART是通用异步收发器，USART还具备同步通信能力。当前工程使用USART2的异步模式，连接中没有单独的时钟线。两端预先约定波特率和字节格式，接收方通过起始位确定一个字节的开始。

基本信号为：

- TX：本端发送数据的引脚。
- RX：本端接收数据的引脚。
- GND：双方信号电平的参考地。

因此连接时，本端TX接对端RX，本端RX接对端TX，双方GND相连。TX/RX支持两个方向同时工作，称为全双工。

### 1.2 波特率与8N1

波特率描述信号符号变化速率。在当前二进制UART中，一个符号承载一个比特，2000000bps表示每秒约200万个比特；它不是每秒200万个数据字节。

`8N1` 的含义是8个数据位、无奇偶校验、1个停止位。发送一个字节还需要1个起始位，因此每字节在线路上占用10个比特时间：

```text
空闲高电平 → 起始位0 → 数据bit0～bit7 → 停止位1
                     数据低位先发送
```

在2Mbps下，每比特0.5μs，每字节约5μs，连续传输的理论数据容量为200000字节/秒。实际应用还受主循环、DMA、USB转串口和上位机处理速度影响。

奇偶校验用于发现部分位错误，停止位用于字节边界恢复；它们不能代替应用层的数据帧校验。当前配置没有奇偶校验，也没有RTS/CTS硬件流控。

### 1.3 字节、文本与应用数据帧

串口只传输字节，不知道某个字节是文字、浮点数还是控制命令。如何把连续字节分成一条命令或一帧波形数据，属于应用协议。

本工程两个方向使用不同格式：

| 方向 | 格式 | 分帧方式 |
|---|---|---|
| MCU → 电脑 | JustFloat二进制浮点数据 | 8个float后跟固定帧尾 |
| 电脑 → MCU | ASCII控制命令 | 以实际LF字节`0x0A`结束 |

例如字符`1`是ASCII字节`0x31`；浮点数`1.0f`在本MCU内存中是四个字节`00 00 80 3F`。不能用打印数字字符串的方式替代当前JustFloat帧，也不能把接收区里的二进制“乱码”当作串口一定配置错误。

## 2. 当前串口硬件与配置

### 2.1 参数表

| 项目 | 固件配置 |
|---|---|
| 外设 | USART2，句柄`huart2` |
| 外设时钟源 | PCLK1 |
| TX / RX引脚 | PB3 / PB4，AF7 |
| 波特率 | 2000000bps |
| 数据位 / 校验 / 停止位 | 8 / None / 1，即8N1 |
| 收发模式 | TX和RX均启用 |
| 硬件流控 | None |
| 过采样 | 16倍 |
| 时钟预分频 | 1 |
| FIFO | 禁用 |
| USART2中断优先级 | 2 |
| TX DMA | DMA1 Channel1，Normal，字节宽度，内存地址递增 |
| 配置的RX DMA | DMA1 Channel2，Circular，字节宽度，内存地址递增 |
| VOFA实际RX方式 | `HAL_UART_Receive_IT()`，每次接收1字节 |
| DMA中断优先级 | 2 |

`MX_DMA_Init()` 启用DMA相关时钟和中断，`HAL_UART_MspInit()` 关联DMA与串口句柄。虽然工程生成了RX DMA配置，当前VOFA代码没有调用 `HAL_UART_Receive_DMA()`，不能据此认为命令已经通过DMA环形缓冲区接收。

### 2.2 与电脑连接

使用支持3.3V逻辑电平和2Mbps的USB转UART接口，按实际板上走线连接：

```text
STM32 / 板端                  USB转UART / 电脑端
PB3  USART2_TX  ────────────→  RX
PB4  USART2_RX  ←────────────  TX
GND            ─────────────  GND
```

这里的信号是MCU逻辑电平UART，不能直接连接带正负电压的RS-232口。转接器上的3.3V供电端和TX/RX逻辑电平配置也不是同一个概念，应按转接器说明核对。

源码只能确定PB3/PB4配置，不能确定电脑上的COM编号，也不能证明板载调试器虚拟串口已经接到这两个引脚。使用板载USB串口或调试器VCP时，应结合原理图检查路由；仅有下载接口不等于已连接USART2。

## 3. MCU发往VOFA+的遥测协议

### 3.1 为什么选择JustFloat

当前固件直接发送浮点数的二进制表示，使用VOFA+的JustFloat数据引擎。官方协议说明要求小端float数据及帧尾 `00 00 80 7F`，与本工程的打包方式一致。见 [VOFA+ JustFloat官方说明](https://www.vofa.plus/docs/learning/dataengines/justfloat/)。

本工程每个float为4字节，一帧固定36字节：

```text
字节0～3    CH0
字节4～7    CH1
字节8～11   CH2
字节12～15  CH3
字节16～19  CH4
字节20～23  CH5
字节24～27  CH6
字节28～31  CH7
字节32～35  00 00 80 7F
```

数据部分使用IEEE 754单精度、小端排列。例：100.0为 `00 00 C8 42`，-100.0为 `00 00 C8 C2`。固定尾部是协议分隔标记，不是第九个测量通道。

### 3.2 八个通道的含义

| 通道 | 源变量 | 含义 | 单位 |
|---|---|---|---|
| CH0 | `foc_motor.loop_spd.speed_ref` | 速度目标；位置模式下是位置环输出 | rpm |
| CH1 | `foc_motor.loop_spd.speed_fbk` | 编码器速度反馈 | rpm |
| CH2 | `foc_motor.loop_cur.id_ref` | d轴电流目标 | A |
| CH3 | `foc_motor.loop_cur.i_d` | d轴电流反馈 | A |
| CH4 | `foc_motor.loop_cur.iq_ref` | q轴电流目标 | A |
| CH5 | `foc_motor.loop_cur.i_q` | q轴电流反馈 | A |
| CH6 | `foc_motor.loop_cur.v_d` | d轴输出电压 | V |
| CH7 | `foc_motor.loop_cur.v_q` | q轴输出电压 | V |

当前帧没有发送母线电压、机械角、电角度、位置目标、位置误差或电机状态。因此仅凭这八条波形不能直接判断当前位置是否精确达到目标，也不能直接读取状态机状态。非RUNNING时，速度反馈会周期更新，但电流环反馈和电压工作量可能保留最后一次控制结果。

### 3.3 发送频率与线路负载

在RUNNING状态，ADC电流回调每四次请求一次遥测，按16kHz设计节拍约为4k次请求/秒。STOPPED、ALIGNING和ALIGN_RELEASE状态由主循环约每10ms请求一次，约100次/秒。

```text
每帧线路位数 = 36字节 × 10bit = 360bit
每帧线路时间 = 360 / 2000000 = 180μs
4k帧/秒负载 = 36 × 4000 = 144000字节/秒
线路理论占用 = 144000 / 200000 = 72%
```

这里是请求频率和理论负载，不是保证每秒收到4000帧。`telemetry_pending` 只有一个标志位：多次请求可以合并；主循环发现TX DMA忙时会丢弃本次请求，不等待、不排队。帧内没有时间戳、序号或CRC，八个变量也没有整组快照锁，不能默认它们全部来自完全相同的控制周期。

采样间隔和显示时间轴应按实际接收情况理解。不要混入任意ASCII `printf()` 输出，接收端会将这些额外字节当作二进制流的一部分。

## 4. 串口与VOFA模块如何工作

### 4.1 文件分工

| 文件 | 职责 |
|---|---|
| `Core/Src/usart.c`、`Core/Inc/usart.h` | USART2配置、GPIO、DMA关联，导出句柄 |
| `Core/Src/dma.c`、`Core/Inc/dma.h` | DMA时钟与中断配置 |
| `Core/Src/stm32g4xx_it.c` | USART2、DMA中断入口，转交HAL |
| `User/foc_vofa.c/.h` | 遥测帧、字符收集、命令解析、模式管理 |
| `User/foc_manager.c` | 初始化VOFA，在主循环调用Tx/Rx处理 |
| `Core/Src/main.c` | RUNNING时在电流回调四分频请求遥测 |

VOFA仅保存 `foc_motor` 内各成员的指针，不创建第二套编码器或控制环对象。头文件的 `FOC_CONTROL_MODE` 定义速度模式和位置模式；它与manager的STOPPED/ALIGNING/RUNNING状态属于不同概念。

### 4.2 各函数具体作用

| 函数 | 作用 | 执行位置 / 可见性 |
|---|---|---|
| `FOC_VOFA_Init()` | 绑定串口和模块指针，默认速度模式，清标志，启动单字节接收中断 | manager初始化，公开 |
| `FOC_VOFA_GetControlMode()` | 返回当前速度/位置模式 | 按键、manager、TIM6回调使用，公开 |
| `FOC_VOFA_RequestTelemetry()` | 只将遥测请求标志置1 | 控制回调或manager，公开 |
| `FOC_VOFA_ProcessTx()` | 消费请求；空闲时读取八个变量、打包36字节、启动TX DMA | 主循环，公开 |
| `FOC_VOFA_ProcessRx()` | 执行已经收完整的一条命令，再清接收状态 | 主循环，公开 |
| `FOC_VOFA_ExecuteCommand()` | 匹配模式命令或解析S/P后的有限浮点数 | `static` |
| `FOC_VOFA_SwitchToSpeed()` | 速度目标清零，复位速度/位置PI，切速度模式 | `static` |
| `FOC_VOFA_SwitchToPosition()` | 首次切入时读当前角度作为位置目标，清速度目标及外环积分 | `static` |
| `HAL_UART_RxCpltCallback()` | 过滤串口，收集一个字节，遇LF发布完整命令，再次启动接收 | UART中断上下文，HAL回调 |
| `HAL_UART_ErrorCallback()` | 对本串口丢弃未完成的命令长度并重新启动接收 | HAL错误回调 |
| `HAL_UART_TxCpltCallback()` | 对本串口释放`tx_busy`，允许提交下一帧 | HAL发送完成回调 |

### 4.3 发送调用链

```text
ADC电流回调每4次 / manager非运行状态每10ms
→ FOC_VOFA_RequestTelemetry()
→ 主循环FOC_VOFA_ProcessTx()
→ memcpy浮点数据 + 固定帧尾
→ HAL_UART_Transmit_DMA()
→ DMA及UART的HAL中断处理
→ HAL_UART_TxCpltCallback()释放busy
```

发送缓冲区是静态数组，发送完成前不会作为下一帧重写，满足DMA异步读取期间的寿命要求。DMA减少CPU逐字节发送的工作，但并不提高串口线路本身的波特率。

### 4.4 接收调用链与长度限制

```text
USART2_IRQHandler()
→ HAL_UART_IRQHandler()
→ HAL_UART_RxCpltCallback()收1字节
→ LF到达，将command_ready置1
→ 主循环FOC_VOFA_ProcessRx()
→ FOC_VOFA_ExecuteCommand()
→ 模式或目标更新
```

命令数组长32字节，最多容纳31个有效字符和字符串结尾。CR字节 `0x0D` 被忽略，LF字节 `0x0A` 才提交命令。因此CRLF可以使用，单独CR不会提交。超长命令整条丢弃，空行不执行。

没有命令队列：等待主循环处理已完成命令时，新收到的字符被忽略。应逐条发送操作命令，不要连续高速灌入一串命令。协议没有ACK或错误文字回复，未知命令、格式错误或非有限数值会静默忽略。

更新外环模式和目标时，代码短暂屏蔽TIM6中断以协调速度/位置任务，然后恢复；ADC电流中断没有因此被屏蔽。这不是对整个 `foc_motor` 的全局锁。

## 5. 电脑发给MCU的控制命令

以下 `\n` 表示实际换行字节LF，不表示发送反斜杠和字母n。命令区分大小写，使用下表的大写形式。

| 示例 | 实际功能 | 需要注意 |
|---|---|---|
| `MS\n` | 切速度模式，目标清零，复位速度/位置PI | 即使已经是速度模式，也会清零目标 |
| `MP\n` | 切位置模式，以当前位置为目标 | 已是位置模式时直接返回，不重新设置位置目标 |
| `S300\n` | 设置速度目标+300rpm | 不自动切换到速度模式 |
| `S-300\n` | 设置速度目标-300rpm | 直接使用负值，无方向标志 |
| `S0\n` | 速度目标设0 | 在速度模式下仍保持闭环和PWM |
| `P1.570796\n` | 设置约π/2rad，即90°的单圈机械角目标 | 不自动切换位置模式 |
| `P0\n` | 设置0rad单圈目标 | 是计数坐标原点，不代表机械回零传感器 |
| `STOP\n` | 执行切速度模式及零速目标的流程 | 没有调用`FOC_Motor_Stop()` |

S/P数值使用 `strtof()` 解析，可带正负号、小数或科学计数形式，但必须确实包含数值且解析后无多余尾随字符。`NaN`、无穷大、`Sabc`、`S100abc` 等会被拒绝。建议发送无额外空格的规范命令。

速度目标最终限制在±2600rpm，超出部分被截断。位置输入先对2π取余，再归一化到 `[0,2π)`；例如 `P-1.570796` 对应约270°，而 `P6.283185` 约等于0°。它们不是相对移动量，也不是要求转指定圈数。

### 5.1 模式、目标和电机启停的区别

模式命令决定哪些外环运行，S/P命令只修改目标，SW1或manager接口决定功率启停。

- 速度模式中发送S，速度PI跟踪该目标。
- 位置模式中发送S，下一次位置环会重新生成速度目标，因此不能用它代替切速度模式。
- 速度模式中发送P，保存了位置目标但当前位置环不运行。
- `S0` 可以产生用于减速、抵抗扰动的q轴电流；`STOP` 切到速度模式后也保持零速闭环。
- SW1调用完整停机链，关闭MOE并停止相关PWM、ADC和TIM6。

当前没有串口 `START` 命令，`STOP` 名称也不等于功率关断命令。需要关断输出时使用SW1；若在代码中调用，使用 `FOC_Motor_Stop()`。

启动流程会清目标，释放结束也重新设置当前位置目标；速度模式启动最后将速度目标设为+100rpm。所以在启动前发送负速目标，并不能保证启动后保留负速。应等待进入RUNNING后再发送目标。运行中发送 `MS` 后再发送 `S-300`，才是明确的反向速度操作顺序。

### 5.2 确认真正发出了LF

若上位机有“追加LF/换行”的选项，可以在文本框只填 `S-100`，启用追加LF。若使用十六进制发送，完整字节应为：

```text
S-100 + LF：53 2D 31 30 30 0A
MS + LF：  4D 53 0A
MP + LF：  4D 50 0A
```

仅发送 `S-100` 而没有最后的 `0A`，固件会一直等命令结束。某些文本框不会自动解释 `\n`；应检查工具的转义/行尾规则，或通过发送十六进制验证。连续使用两个工具打开同一个串口也可能导致占用冲突。

## 6. VOFA+上位机操作

### 6.1 建立连接并显示波形

VOFA+通过通信接口接收数据，通过数据引擎解析，再将通道绑定到波形控件。官方快速入门演示了接口、协议选择及控件Y轴绑定，参见 [VOFA+快速入门](https://www.vofa.plus/docs/learning/start/quick_start/)。该教程的文本协议例子需要替换为本工程的JustFloat。

1. 启动VOFA+，选择串口通信接口及实际出现的COM端口。
2. 设置波特率2000000、8数据位、无校验、1停止位、无流控。电脑和固件必须一致。
3. 数据引擎选择 **JustFloat**，打开连接。不要按文本CSV配置FireWater来解析本固件。
4. 放置波形控件，将Y轴数据绑定到解析出的CH0～CH7；可按用途分为速度、电流、电压三个图。
5. 给曲线设置清楚的名称和单位，例如 `speed_ref/rpm`、`iq_fbk/A`。数据有变化后使用合适的自动缩放或手动范围。
6. 非RUNNING时也应收到约100Hz请求产生的遥测；速度可能为0，其他量可能尚未更新。进入RUNNING后观察更密集的反馈变化。

推荐先显示CH0/CH1比较目标与反馈，再显示CH4/CH5比较q轴电流。不要把rpm和安培直接当作同一量纲看误差。

JustFloat为二进制，文本接收窗口出现不可读字符通常是正常现象。诊断时改用十六进制视图，查找每36字节一组的尾部 `00 00 80 7F`，并确认波形引擎和帧格式匹配。[官方JustFloat说明](https://www.vofa.plus/docs/learning/dataengines/justfloat/)也提供了十六进制观察方法。

### 6.2 发送命令和配置按钮

在当前版本的发送区域选择ASCII/文本方式，并设置实际LF行尾；逐条发送第五节命令。使用自定义按钮时，可分别绑定 `MS`、`MP`、`S300`、`S-300`、`S0`、`P0` 等完整命令，确保按钮发送的最终字节包含LF。

发送按钮不需要把命令包装成JustFloat；JustFloat负责接收MCU发来的波形数据，MCU接收的是ASCII命令。命令发送和波形接收可以同时进行。

按钮若命名为“停机”，必须意识到当前 `STOP` 只进入零速速度模式。建议将其标成“零速”，将板上SW1用于功率停机，避免界面名称误导。

## 7. 一次完整的速度与位置操作

### 7.1 速度模式：正转、零速、反转

1. 连接串口并确认JustFloat可接收，板上仍处于STOPPED。
2. 按SW1。等待对齐保持、角度采样和释放稳定完成，正常约1.8秒以上。默认速度模式进入RUNNING后，速度目标为+100rpm。
3. 发送 `MS` 加LF，确认切速度模式并清零目标。
4. 单独发送 `S300` 加LF，观察CH0约300、CH1逐渐跟踪。
5. 单独发送 `S0` 加LF，观察反馈趋向零；PWM仍保持运行。
6. 单独发送 `S-300` 加LF，观察CH0为负、CH1跟踪负转速。
7. 按SW1，执行真正的功率停机。

SW2/SW3也可实现 `+100 → 0 → -100` 的带符号调速，每次按下事件改变100rpm。长按不会连续调速。波形中的正负方向由当前接线和编码器计数方向约定，不能仅凭源码判断观察者看到的顺/逆时针。

### 7.2 位置模式：单圈定位

1. 按上述方法完成启动并进入RUNNING。
2. 发送 `MP` 加LF。固件读取当前位置作为目标，并复位外环积分；这次切换本身用于保持切入位置。
3. 单独发送 `P1.570796` 加LF，将目标设为约90°机械角。
4. 查看CH0/CH1了解位置环产生的速度和实际速度，查看CH4/CH5了解定位期间的电流。
5. 单独发送 `P0` 加LF，按最短单圈角度路径回到当前计数坐标的0rad。
6. 要重新直接调速，先发 `MS` 加LF，再单独发S命令。要关闭输出，按SW1。

位置坐标的0点来自TIM3上电清零，不是永久机械零点。对齐校准解决的是电角度偏置，不能替代机械回零。当前遥测没有机械角和位置误差，精确位置验证需要通过调试器查看 `foc_motor.encoder.angle_m`、`foc_motor.loop_pos.position_ref` 等变量或使用外部测量；本文没有修改遥测协议。

## 8. 常见问题与排查

| 现象 | 对应检查 |
|---|---|
| 找不到COM或无法打开 | USB转串口驱动、端口是否被占用、适配器是否正常枚举 |
| 能下载程序但没有串口数据 | 下载接口未必接USART2；核对PB3/PB4与桥接器实际走线 |
| 原始接收是乱码 | 先判断是否正在看JustFloat二进制；切十六进制并核对2Mbps/8N1 |
| 有字节但没有波形 | 检查JustFloat引擎、36字节/8通道格式、帧尾和Y轴绑定 |
| 命令发送后目标不变 | 检查大写格式、LF、模式、是否已RUNNING、命令是否被启动流程覆盖 |
| 发送S后又被改回 | 在位置模式中，位置环会覆盖速度目标；先发MS |
| 发送P后不定位 | P不切模式，先发MP；确认功率状态已RUNNING |
| 连发命令有遗漏 | 当前只有一条命令缓冲，没有队列；改为逐条发送 |
| 发送STOP后仍有PWM | 当前实现就是零速速度模式；功率关闭使用SW1 |
| 启动前设-300，启动后变+100 | 启动链重设了目标；RUNNING后再发送S-300 |
| 波形速率不稳定 | 遥测请求合并、DMA忙丢帧、主循环和USB处理均可影响实际帧率 |
| 波形中没有母线或位置 | 当前仅八个固定通道，查第三节映射，不要将其他通道误认为角度 |
| 串口错误后部分命令丢失 | 错误回调丢弃半条命令并重启IT接收；上位机需重新完整发送 |

这些排查说明当前协议行为，不代表已经进行上板串口压力测试。本文仅新增使用说明，没有改波特率、ISR、控制参数或通信代码。
